## Hugging Face 신규·갱신 VLM 및 YOLO 등 비전 모델

### 기존 VLM의 새 실행 형식 — Liquid AI LFM3-VL-2B

[원본 모델 카드](https://huggingface.co/LiquidAI/LFM3-VL-2B)는 **1.92B**(언어 1.73B·영상 인코더 164M·프로젝터 25M), 이미지/영상 질의응답·문서/차트·공간 추론, 128K 최대 문맥, BF16 Safetensors 및 [LFM Open License v1.0](https://huggingface.co/LiquidAI/LFM3-VL-2B/blob/main/LICENSE)을 명시한다. 원본 모델 공개는 10월 말이며 11/3 **새 모델 자체 출시가 아니다**. [공식 GGUF 저장소](https://huggingface.co/LiquidAI/LFM3-VL-2B-GGUF)의 11/3 **13:31:53 UTC** 커밋은 별도 NVFP4 체크포인트에서 변환한 `LFM3-VL-2B-NVFP4.gguf`를 추가한다. 언어 피드포워드 부분만 NVFP4, 나머지는 Q8_0, 비전용 `mmproj`는 별개다. 메인 파일 **1,280,020,064바이트**와 기존 Q8_0 `mmproj` **203,031,872바이트**는 각각 저장소 파일 크기; 필요 메모리·KV·영상 버퍼는 미확인. 14:49 UTC의 다음 카드 수정은 국내 **23:49 KST**이며 llama.cpp `b12088` 지원을 문서화했다. 최초 업로드 시에는 가중치 스케일 수정 전 구버전이 출력 오류를 낸다는 경고가 있었으므로 런타임 빌드를 반드시 고정해 비교해야 한다. 4비트 이름만으로 전 기기에서 빠르다고 단정하지 않는다.

### 신모델 발표와 기존 객체 탐지기 구별

배키 비전 3B는 **신규 발표지만 공개 가중치는 미확인**: 영상 공간·로봇·문서 질의응답 목적의 약 3B급이라는 보도자료 표현 외 정확한 파라미터 계수, 체크포인트 형식, 라이선스, 양자화 정보는 공개 확인 불가다. 제조 안전 판단은 실물 장비에서의 독립 테스트 전 보류한다. [Tencent WeVisOne-VL-2B](https://huggingface.co/tencent/WeVisOne-VL-2B)와 [4B](https://huggingface.co/tencent/WeVisOne-VL-4B)는 탐지·OCR·분할·매팅을 묶은 **기존 공개 모델**(허브 표시 2.44B/4.83B, Safetensors, Apache-2.0, **10/23 갱신**)이다. 11/3 제3자 기사·미러가 있더라도 당일 원본 가중치 공개로 보지 않는다. 제작자 [평가표](https://github.com/Tencent/WeVisOne-VL)는 자체 선택 비교이며 2B의 영상 격자 입력은 픽셀 디코더가 거부한다고 명시한다.

**YOLO 별도 분류:** [Ultralytics v8.4.199](https://github.com/ultralytics/ultralytics/releases/tag/v8.4.199)(11/3 09:56 KST)은 단일 클래스 의미 분할 플롯·OOM 재시도·TensorRT 프로파일링을 수정했다. [v8.4.200](https://github.com/ultralytics/ultralytics/releases/tag/v8.4.200)(19:37 KST)은 산업 안전장비용 Construction-PPE 데이터셋 **1,000장, 12종, 검토 주석 14,863개**(제작사 표기), INT8 내보내기의 적은 보정 영상 배치 처리를 수정했다. [v8.4.201](https://github.com/ultralytics/ultralytics/releases/tag/v8.4.201)(21:37 KST)은 PIL 기반 시각화 최대 15배 향상을 **제작사 주장**으로 발표하고 데이터셋 경로를 통일했다. 세 릴리스 모두 **새 아키텍처 아님**. [YOLO26](https://docs.ultralytics.com/models/yolo26)는 기존 탐지·인스턴스/의미 분할 계열이며, 모델 정확도나 추론 속도 상승과 도구의 플롯 속도를 구분해야 한다. 코드 AGPL-3.0/상용 이중 라이선스는 배포 전 검토한다.

## Decisions API 및 오픈 웨이트 의사결정 모델

[OpenAI 공식 변경 기록](https://developers.openai.com/api/docs/changelog)의 최신 2026년 항목은 10/30이며 Decisions의 마지막 변경은 **10/22 일반 제공**이다. 11/3 신규 변경·요금·지연 측정 발표를 확인하지 못했다. [공식 가이드](https://developers.openai.com/api/docs/guides/decisions)에 따르면 `POST /v1/decisions`는 텍스트·이미지·JSON을 평가하는 **호스팅 API**이고, 유일 지원 모델은 `gpt-6-luna`다. `predicate`는 참 확률, `choice`는 지정 후보 중 선택·확률, `score`는 순서형 등급 분포의 가중 평균을 반환한다. 가이드 표기 기준 입력 100만 토큰당 미화 **$0.10**, 출력 과금 없음; 지역 처리·긴 문맥 배수와 10/22에 추가된 캐시 할인 적용 조건은 별도로 확인해야 한다. **문서 간 상태 불일치:** 공식 변경 기록은 10/22 일반 제공이라고 적지만 가이드 머리말에는 여전히 공개 베타라고 적혀 있다. 이번 조사에서는 더 최근 날짜가 명시된 변경 기록을 기준으로 보되 공식 문서 정합성은 미확인이다. 제공사의 Responses API 대비 약 10배 빠르다는 문구는 **벤더 자체 주장**이며 독립 지연 실측이 아니다. 이 API를 오픈 웨이트로 세지 않는다.

**공개 시점 주의 — Hindsight:** [공식 블로그](https://hindsight.vectorize.io/blog/2026/11/03/hindsight-models)는 **11/3 날짜**로 0.8B `hs-decide-1-flash`, 메모리 정리용 재순위화·임베딩 모델을 발표했다. 그러나 [HF 저장소](https://huggingface.co/hindsight-ai/hs-decide-1-flash/commits/main)의 유일한 가중치·카드·서빙 코드 최초 커밋은 **11/3 21:18:01 UTC = 11/4 06:18 KST**이다. 따라서 **11/3 오픈 가중치 신규 공개는 확인되지 않음**. 비교를 위한 최초 참조: [카드](https://huggingface.co/hindsight-ai/hs-decide-1-flash)는 `Qwen3.5-0.8B` 기반 **752,393,024개 BF16**, Apache-2.0, 약 1.5GB 가중치 파일·vLLM 0.32.0 플러그인, `choice`/`score`/`noul`(yes/no) 확률을 제시한다. 직접 `/v1/systemone`으로 요청하며 **OpenAI `/v1/decisions` 요청 형식과 호환되지 않는다**. 원본 가중치·서빙 코드 공개는 확인했지만 학습 데이터 전체와 양자화 체크포인트는 미확인이다. 8/16/32GB mini PC와 GB10 실측 메모리·지연도 미확인. BF16 가중치만 752,393,024×2바이트 **약 1.50GB 계산 추정**, 캐시·런타임 제외다. 공급자의 Hindsight 업무 평가(판정 호출 중앙값 167ms; 다수 LLM 개선)는 같은 제품 흐름의 자체 평가이며 독립 공통 분할 성능이 아니다. 공개 학습셋/시험셋 분리·정확도·Brier/ECE·후보 순서 바꾸기 실험을 맞춰 보기 전 OpenAI와 숫자를 직접 비교하지 않는다.

의사결정 모델은 짧은 답을 자유 생성하는 일반 추론 LLM이나 강화학습 궤적의 보상 조건부 행동을 예측하는 Decision Transformer와 다르다. 고객 분류·증거 충분성 판단은 확률 보정과 사람 검토 임계값을 별도 설계해야 한다.

## AI/Vision 업무 적용 판단·한계

**분석:** 제조 카메라·용접 영역에서는 NC AI의 공급자 점수보다 샘플링 시간, 결함 재현율, 야간 조명·가림·한글 표기, 실패 시 사람 확인 비율을 먼저 정해야 한다. 공개 체크포인트가 없는 배키 모델은 로컬 미니 PC·GB10 검증 대상으로 즉시 구매하지 않는다. Liquid의 새 GGUF는 이미지 질의응답과 현장 도면 파일의 탐색용 후보이지 독립 탐지기 또는 제어기가 아니다. YOLO26 도구 업데이트 후 Construction-PPE 기존 클래스 번호를 기대하는 데이터 전처리·평가기를 그대로 두면 오분류가 날 수 있다. Auto Ontology는 메타데이터 정의·데이터 계보에 사람이 승인한 기준을 넣고, 격리된 비민감 테스트 DB에서 의미 외래키 제거 결과를 비교해야 한다. 내부 코드·고객 데이터·센서 기록을 외부 모델/API로 송신하지 않았고 로봇 동작·보정 명령도 하지 않았다. 모델 추론 재현 시험과 독립 벤치마크는 이번 조사 범위 밖이다.
