## Hugging Face 경량 VLM과 별도 비전 모델

### 신규·기존 업데이트를 구분한다

- **신규 저장소 — [arlenecc/OvisOCR2-0.8B-MLX-4bit](https://huggingface.co/arlenecc/OvisOCR2-0.8B-MLX-4bit):** [커밋](https://huggingface.co/arlenecc/OvisOCR2-0.8B-MLX-4bit/commit/355982edaf2459dd0f2cd806231ceff2ed7e063d) **11월 1일 14:01 UTC/23:01 KST**. 기존 [ATH-MaaS/OvisOCR2](https://huggingface.co/ATH-MaaS/OvisOCR2)를 MLX로 변환한 **새 배포본, 새 기반 모델이 아님**. 문서 이미지의 텍스트·표를 읽어 구조화한다. 카드상 852.99M 파라미터, Apache-2.0, MLX Safetensors, 언어 부위 4비트·비전 타워 BF16, 디스크 0.63GB. 제작자 보고 M2 Pro 32GB에서 최대 RAM 0.86GB·5개 합성 문서의 숫자 재현; 실제 스캔·한글 문서·필기체·복잡한 표 구조에 대한 독립 평가는 없다. 카드 예시 명령이 **다른 저장소 이름을 가리키므로** 그대로 복사해 재현했다고 주장하지 않는다.
- **신규 파생 모델 — [AbstractPhil/Lucia 2B 어댑터](https://huggingface.co/AbstractPhil/qwen3.5-2b-think-symbolic-image):** [11월 1일 06:01 UTC/15:01 KST](https://huggingface.co/AbstractPhil/qwen3.5-2b-think-symbolic-image/commits/main) 최초 LoRA 공개, [09:17 UTC/18:17 KST](https://huggingface.co/AbstractPhil/qwen3.5-2b-think-symbolic-image/commit/821b257ee96a) 카드 갱신. 기존 Qwen3.5-2B 기반 이미지의 설명·짧은 시각 추론을 구조화한다. **2B는 기반 모델의 계열 표기**, 별도 어댑터의 실제 계수는 미확인. Apache-2.0, Safetensors LoRA, 기반 모델은 별도 다운로드; 양자화 미표기. 제작자 예시는 영어이며 한국어 문서 OCR 대체재가 아니다. 독립 성능/메모리 수치 미확인.
- **기존 변환본 메타데이터 갱신 — [litert-community/LFM2.5-VL-450M](https://huggingface.co/litert-community/LFM2.5-VL-450M):** [11월 1일 14:48 UTC/23:48 KST 커밋](https://huggingface.co/litert-community/LFM2.5-VL-450M/commit/17581fc10cc3d9375154f9849e520cc2a4cab7b0)은 manifest의 `vision: false`를 `true`로 바꿨다. **새 가중치나 새 출시가 아니다.** 450M(원본 카드 448.72M), 원본은 LFM Open License v1.0이고 변환 저장소 표기는 `other`, LiteRT-LM int4 0.41GB/int8 0.56GB. 원본 32,768토큰과 배포 manifest 4,096토큰은 같지 않다. 저장소는 표준 런타임에서 영상 상단만 읽히는 위치 인식 오류를 명시하며, 수정 묶음도 위치 좌표 신뢰성은 확보하지 못했다고 적는다. 위치·개수 판단에 투입 금지.

**메모리 해석:** 0.63GB와 0.41GB는 **배포 파일 크기**, 실제 최소 RAM/VRAM이 아니다. Ovis의 0.86GB는 제작자의 M2 Pro 측정값으로, 영상 인코더·이미지·토큰 캐시와 런타임 여유는 별도다. Lucia BF16 기반 2.21B 기준 가중치만 약 **4.42GB(2바이트/계수의 계산 추정)**이며 비전 입력·KV 캐시·LoRA 및 운영체제 여유는 포함하지 않는다. 모델마다 입력 해상도·컨텍스트에 따라 달라져 나머지 최소 용량은 **미확인**이다.

### YOLO와 탐지·분할 모델은 VLM과 분리한다

[Ultralytics YOLO26 공식 문서](https://docs.ultralytics.com/models/yolo26)는 탐지와 인스턴스·의미 분할, 자세 등 기존 제품군을 설명한다. 공개 목록에서 당일 일반 목적 **새 YOLO 세대 발표는 확인되지 않았다**. [10월 31일 19:48 UTC/11월 1일 04:48 KST 수정](https://huggingface.co/athkot/repair-table-screws-yolo26s) 등 개별 YOLO 체크포인트는 특정 합성 데이터용으로 표시되며 YOLO26 자체 출시와 구별한다. 해당 수치는 합성 검증 분할에만 적용되므로 실제 설비 성능으로 전용하지 않는다.

대신 [forkger/manga-panel-rfdetr](https://huggingface.co/forkger/manga-panel-rfdetr)는 [11월 1일 12:01 UTC/21:01 KST 실제 파일 업로드](https://huggingface.co/forkger/manga-panel-rfdetr/commit/9654de64b82109570b66e2cbc8fcc36780cd8452)로 확인한 **신규 특화 탐지기**다. RF-DETR Medium 기반, Apache-2.0, Core ML FP16 약 58MB이며 **파라미터 수는 카드에 없어 미확인**. 상자 탐지에는 세 범주가 있고 글자 자체는 읽지 않는다. 제작자 보유 도서 분리 실험의 AP는 외부 데이터 재현 성능이 아니다. iPhone 온디바이스 속도는 제작자 측정이며 mini PC나 GB10 성능이 아니다. [Genellect/Cytellect](https://huggingface.co/Genellect/Cytellect)는 같은 날 카드 설명만 수정된 기존 현미경 분할 모델로, 신규 체크포인트가 아니라 보조 관찰 대상으로 둔다.

## AI/Vision 업무 적용 판단과 한계

**우선 읽기 전용으로:** 문서 OCR은 Ovis MLX의 합성 문서 수치를 실무 한글 라벨·뒤틀린 영수증·표 병합 셀에서 재현해야 한다. RF-DETR 만화 패널 탐지는 비전 파이프라인의 **작업 분리 참고**로 볼 수 있지만 산업 부품 탐지의 성능 근거로 쓰지 않는다. LFM LiteRT-LM의 상단만 인식하는 문제는 조용히 틀린 위치 답변을 만들므로 로봇 행동이나 검사 판정에 연결하지 않는다.

**에이전트 PoC에는:** OpenBot의 금전 이동 분류와 AiSOC의 모델 정체성·전체 표본 분모를 실무 요구사항으로 검토할 만하다. 다만 두 저장소를 설치·실행·보안 감사하지 않았으므로 구현 효과는 주장하지 않는다. 외부 서비스로 고객 문서·센서 영상·내부 코드를 전송하지 않았고 로봇 동작도 실행하지 않았다. 장치 사양, 라이선스의 파생 사용 조건, 정확도와 지연은 실제 기기에서 승인된 데이터로 별도 시험해야 한다.
