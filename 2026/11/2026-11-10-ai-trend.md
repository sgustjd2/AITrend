## Hugging Face 비전 모델과 하드웨어 적합성

**새 저장소: WeVisOne-VL-4B 변환본.** [Hub 모델·카드](https://huggingface.co/litert-community/WeVisOne-VL-4B)에서 10일 08:17 UTC(17:17 KST) 저장소 생성과 08:23 UTC(17:23 KST) int4 LiteRT-LM 파일 추가를 확인했다. Tencent 원본 4B 기반이며 변환 저장소는 Apache-2.0 표기다. 카드에 따르면 int4 디코더와 int8 임베더, float16 비전 인코더를 섞은 단일 파일 3,507,874,304바이트, 문맥 2,048토큰이다. 한 장의 사진으로 물체 탐지·지시 대상 좌표·개수·OCR을 구조화 텍스트로 출력한다. 마스크용 원본 픽셀 디코더가 빠져 세그멘테이션과 매팅은 못 한다. 카드 게시자의 Galaxy S26 GPU 시험은 첫 토큰 4.86초, 사진 처리 최대 메모리 3.78~3.79GB라고 적지만 두 프로세스의 중간값이고 작은 자체 문제 세트이므로 일반 성능이라고 확장하지 않는다. [대상일 카드 이력](https://huggingface.co/litert-community/WeVisOne-VL-4B/commit/cfe3cff01ca3), [측정 근거](https://huggingface.co/litert-community/WeVisOne-VL-4B/blob/main/MEASUREMENTS.md), 시험 표기는 2026-11-10.

**새 저장소: Xiaomi-OCR-0-mlx-4Bit.** [Hub 카드](https://huggingface.co/lucasafoliveira/Xiaomi-OCR-0-mlx-4Bit)는 원본 Xiaomi-OCR-0의 제3자 MLX 4비트 변환이라고 명시한다. Hub 생성·업로드는 10일 14:24 UTC(23:24 KST), 라이선스 표기는 Apache-2.0, 파일은 `model.safetensors`다. OCR·문서 이해 태그가 있지만 카드의 유일한 예시는 일반 텍스트 `hello` 생성이라 실제 이미지 OCR 입력이 이 변환본에서 작동하는지는 검증되지 않았다. 저장소 메타데이터의 파라미터 합계 752,393,024개는 Hub 표기일 뿐 재계산하지 않았으며, 양자화 이름만으로 메모리·정확도·상용 적합성을 단정하지 않는다. [업로드 커밋](https://huggingface.co/lucasafoliveira/Xiaomi-OCR-0-mlx-4Bit/commit/8adf9727bdb2), 2026-11-10 14:24 UTC.

**탐지기와 세그멘테이션을 분리할 것.** WeVisOne의 박스·점은 비전언어 질의 응답이고 픽셀 마스크가 아니다. Ultralytics의 YOLO 릴리스 v8.4.209는 [공식 릴리스](https://github.com/ultralytics/ultralytics/releases/tag/v8.4.209)가 2026-11-10 18:54 UTC(11일 03:54 KST)이므로 이번 대상일 뉴스로 쓰지 않는다. 해당 릴리스의 동시 예측 설정 격리 개선도 새 탐지 모델 출시와 다른 소프트웨어 수정이다.

|---|---|---|---|

위 표는 **실행 보증이 아닌 미검증 항목의 분리**다. 가중치 파일 크기는 활성화, 영상 인코더, 키·값 캐시, 컨텍스트, 런타임 오버헤드를 포함하지 않는다. GB10 및 각 mini PC의 실제 메모리 구성·공식 요구량을 함께 확인하지 못했으므로 적합성 합격·필요 메모리를 숫자로 추정하지 않는다.

## Decisions API와 공개 가중치 판정 모델

[OpenAI Decisions 공식 안내](https://developers.openai.com/api/docs/guides/decisions)는 `predicate`를 명제의 확률, `choice`를 주어진 선택지의 판정, `score`를 순서형 등급 판정으로 설명하는 **호스팅 API**다. 공식 안내가 명시한 입력은 텍스트·이미지·JSON이다. 영상 입력 지원은 이 문서에서 확인하지 못했다. 대상일 개정 이력, 요금 및 지연의 대상일 변화도 확인되지 않았다. 이를 다운로드 가능한 오픈 웨이트 또는 일반 대화형 추론 LLM, 궤적을 다루는 강화학습 Decision Transformer와 동일 범주로 놓지 않는다.

[Valen-Decision-1.5-27B-ONNX](https://huggingface.co/Valen-Team/Valen-Decision-1.5-27B-ONNX)는 11월 4일 생성된 기존 저장소이며 10일 14:45 UTC(23:45 KST) [ONNX v2 묶음 교체](https://huggingface.co/Valen-Team/Valen-Decision-1.5-27B-ONNX/commit/1bcbd0a69069cf8ee693b2c91481985189d5bb36)를 확인했다. 카드 표기는 Apache-2.0, 27B 계열, 이미지·영상·텍스트를 입력으로 한 명제 확률·선택·등급·위치 판정이며 공개 ONNX 파일과 [학습 코드](https://github.com/Valen-Team/Valen)를 안내한다. 학습 데이터는 공개되지 않았다고 카드에 명시한다. 카드가 주장하는 OpenAI Decisions 유사 호출 형식은 사용 시점 라이브러리와 엔드포인트의 실제 호환 테스트를 뜻하지 않는다. 별도 CUDA fp16 파일과 설치 안내의 10일 17시 UTC 갱신은 **11일 KST**이므로 이번 대상일 변경으로 합치지 않는다.

**비교 기준과 한계:** 실무에선 세 유형의 출력 스키마·텍스트/영상 처리·사업자 호스팅 대 로컬 가중치·데이터 경계를 먼저 맞춰야 한다. Valen 카드의 자체 Decision Index와 API 사업자 측정은 독립 평가가 아니다. 동일 데이터셋·분할, 정확도, Brier/ECE 확률 보정, 선택지 순서 교란, 입출력 지연, 27B 양자화·전체 피크 메모리를 동일 조건에서 대조한 근거가 없어 우열을 정할 수 없다. 27B ONNX 파일의 정확한 실행 메모리, mini PC/GB10 가능성도 미확인이다. 비식별 내부 샘플로 검증하되 원본 고객 자료를 외부 API에 보내지 않는 것이 선행 조건이다.

## AI/Vision 업무 적용 판단과 한계

**우선 시험:** WeVisOne은 단일 사진의 좌표·OCR을 실험하되 마스크가 필요한 현장이라면 YOLO 세그멘테이션/별도 마스크 모델과 평가 경로를 분리한다. Xiaomi 변환본은 문서 이미지 입력 예제가 카드에 없으므로 테스트 픽스처를 마련해 기본 OCR부터 확인한다. Valen은 판정 스키마와 확률 보정을 먼저 평가하고, 임계값/클래스별 오탐 비용을 따로 정해야 한다. 세 모델 모두 mini PC·GB10에서 실행을 성공했다고 주장하지 않는다. **운영 판단:** Toss Tech의 사례는 샌드박스 마운트·목적지 허용 목록·세션 영속화 분리의 설계 참고자료이지 배포된 제품의 보안 보증이 아니다. 고객 자료·내부 코드의 외부 전송은 별도 승인 전 금지한다.
