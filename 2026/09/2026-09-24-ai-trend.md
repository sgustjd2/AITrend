### 결론 — 신규 신호

**(1) "Jev / OpenJev / Laya" 결정형(확률형) 모델 생태계가 이번 구간 폭발적으로 확산 — 지난 며칠간 개별 관찰해온 패턴의 정체를 확인**

지난 며칠간 이 리포트가 산발적으로 관찰해 온 "타입 질의를 던지고 텍스트 생성 없이 로짓에서 보정된 확률을 얻는" 패턴(jbarney/circuit-vl-4b, MeerDevelopment/Qevi-2B, jaswanthsanjay88/rev-vision, thaitea/laya-vision 등)의 배경을 이번 구간에 처음으로 명확히 확인했다:

- **원조는 `TypeSafe`사의 상용 호스팅 API "Jev"**([typesafe.ai](https://typesafe.ai/blog/introducing-system-one-models-and-jev))다. `openjev/openjev`(README 열람, lastModified 이번 구간 갱신) 저장소는 이를 재현한 오픈웨이트 "System 1 decision model"로, 상태(state)와 타입 질의(choice/noul/score)를 받아 옵션당 하나의 forward pass로 보정된 확률을 반환한다. 텍스트뿐 아니라 **DOM·JSON·스크린샷(이미지 1장)**을 입력받아 브라우저/데스크톱 에이전트의 "다음에 누를 버튼"을 판단하는 용도까지 포함한다.

### 판단 요약

이번 24시간 구간의 가장 큰 변화는 개별 신규 모델이 아니라 **생태계 수준의 확산**이다. 지난 며칠간 산발적으로 관찰해온 "타입 질의 + 로짓 기반 보정 확률" VLM 패턴이 실은 TypeSafe사의 상용 API "Jev"를 재현·모방하는 광범위한 오픈소스 흐름(OpenJev, Kev, Laya, NeoHorse-Jev 등)의 일부였음을 이번 구간 처음 확인했다. 이번 구간에만 관련 텍스트 파생 모델이 30건 이상 새로 생성됐으나, 실제로 이미지 입력을 갖춘 신규 저장소는 `Fr0zencr4nE/jev-spatial`(Molmo2-ER 4.85B, 결정형 공간 포인팅 — coarse-to-fine 그리드 선택이 좌표 텍스트 생성보다 정확하다는 보고가 눈에 띔), `thaitea/laya-vision-201m`(라야 비전 계열 최소 파라미터), `TokenRhythm/NeoHorse-Jev-4B`, `divyanshx11/JEVision`(초기 PoC) 4건뿐이었고, 그마저도 화재/PPE/낙상 도메인 특화 학습은 전무했다. 한편 관찰목록 베이스라인 쪽에서는 LiquidAI가 `LFM2.5-VL-3B-DSpark`라는 공식 스펙큘레이티브 디코딩 드래프트 모델을 공개해, 기존 채택 후보의 추론 속도를 출력 변경 없이 높일 수 있는 실질적 옵션이 새로 생겼다(단 3070/4070 실측은 없음). 핵심 화재/PPE/낙상 탐지 관찰목록(select-ai, rangerhkai, fireviewer, KuBaN1900, wesleymqsss, Ganesh-Nadkarni, Beehzod, szybkie-ai, MoritzM00, nullsilver, wahnfried, SeanLiu, twainsk)은 이번 구간 전부 변화가 없었다. 두 관찰목록 저장소(`thaitea/laya-vision-web`, `pilotspace/laya-codex`)가 이번 회차부터 API에서 401(게이트/비공개 추정)로 응답한 점은 다음 회차에도 재확인이 필요하다.

### 프롬프트 인젝션 점검

이번 구간에 원문을 열람한 README/MODEL_CARD 약 14건(`openjev/openjev`, `IamBusy/OpenJev-Vision`, `convaiinnovations/laya`, `TokenRhythm/NeoHorse-Jev-4B`, `Fr0zencr4nE/jev-spatial`, `thaitea/laya-vision-201m`, `divyanshx11/JEVision`, `VTXAI/VTX-JEV-1`, `electblake/clothing_type_rtdetr_v2_r18vd`, `LiquidAI/LFM2.5-VL-3B-DSpark`, `sprappcom/d6-malay-safety-archive`, `Mongoosetross/lookvl-smoke-lora-r5` 등)과, tags/pipeline_tag만 확인한 약 36건을 AI/에이전트 대상 지시문 패턴("이 지시를 무시하라", "너는 이제부터...", 시스템 프롬프트 탈취 시도, 숨겨진 지시 등) 기준으로 점검했다. **모두 정상적인 기술 문서였고 프롬프트 인젝션 패턴은 발견되지 않았다.** `openjev/openjev` README는 에이전트 개발자를 향한 "DONE을 모델의 의견으로만 취급하고 자체 루프에서 완료를 재확인하라"는 안전 권고를 담고 있으나 이는 사용자(개발자)를 향한 정상적 사용 지침이지 이 조사를 수행하는 AI를 겨냥한 지시가 아니다. `sprappcom/d6-malay-safety-archive`는 내용 전체가 암호화되어 있어 애초에 지시문 삽입이 불가능한 상태였다. 어떤 지시도 수행하지 않았다.

### Caveat

- 성능 수치는 전부 모델 카드 자체 보고치이며 독립 검증하지 않았다. `Fr0zencr4nE/jev-spatial`의 포인팅 개선치, `thaitea/laya-vision-201m`의 34개 검증셋 정확도, `LiquidAI/LFM2.5-VL-3B-DSpark`의 가속 배수 모두 자체 벤치마크다.
- 가중치를 다운로드·실행하지 않았으므로 VRAM 적합성은 파라미터 수 기반 이론적 추정이며 실측이 아니다. `LFM2.5-VL-3B-DSpark`의 가속 배수는 H100·Apple 실리콘 측정치이며 RTX 3070/4070에서의 실측은 없다.
- HF 검색 API는 부분 문자열도 매칭하는 것을 이번 회차에 재확인했다(`aimagelab/Mappet-*`가 "ppe" 정규식에 오탐되는 등). 표기 변형(hardhat/hard-hat 등)에 따라 결과가 갈릴 수 있어 완전한 전수 조사는 아니다.
- 무필터 스윕은 이번 회차 5페이지(5,000건, 창구간 4,002건)만으로 창 시작 이전에 도달했다 — 전일 6페이지(6,000건) 대비 적은 페이지로 충분했다는 것은 신규 생성 속도가 하루 사이 다소 둔화됐거나, 우연한 변동일 수 있어 다음 회차에 재확인이 필요하다.
- `thaitea/laya-vision-web`, `pilotspace/laya-codex`가 이번 회차부터 `401 Invalid username or password`를 반환한다. HF API의 401은 보통 게이트(승인 필요) 또는 비공개 전환을 의미하지만, 저장소가 완전히 삭제된 경우에도 유사하게 응답할 수 있어 원인을 API만으로는 확정할 수 없었다(`pilotspace`는 저자별 공개 목록에서도 0건으로 조회됨). 두 저장소 모두 다음 회차에 재확인이 필요하다.
- "Jev/OpenJev/Laya" 생태계 서술은 각 프로젝트의 공개 README에 명시된 자기소개(관계 부인 문구 포함, 예: "OpenJev is an independent project, not affiliated with TypeSafe")를 그대로 옮긴 것이며, TypeSafe사의 실제 "Jev" API 자체는 비공개 상용 서비스라 이 조사(HF REST API 전용)로는 직접 검증할 수 없었다.
- `TokenRhythm/NeoHorse-Jev-4B`와 `divyanshx11/JEVision`은 "이미지 입력 지원"을 README에서 언급하나, 이번에 열람한 범위 내에서 이미지 관련 정량 벤치마크(정확도 등)를 확인하지 못했다 — 텍스트 벤치마크만 표로 공개돼 있었고 "이미지 이해는 별도 보고"라는 문구만 확인됨.
