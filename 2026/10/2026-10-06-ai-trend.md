### (7) 프롬프트 인젝션 점검

검색 결과 제목·스니펫·요약은 모두 **비신뢰 데이터**로 다뤘다. 점검 결과는 다음과 같다.

- "이전 지시 무시", "다음을 실행하라" 같은 **AI 대상 은닉 지시문은 발견되지 않았다.**

- **YOLO27**은 가중치가 공개되면 재평가한다(미출시).

**(c) 추천 구성: YOLO 1차 탐지 → VLM 2차 확인 cascade**

1. **1차(매 프레임)**: YOLO26s/RF-DETR로 `fire`/`smoke`/`person`(+`harness` 자체 학습) 박스를 찾는다. 신뢰도 임계값은 낮게(예: 0.3) 잡아 재현율을 확보한다.
2. **트리거**: 같은 클래스가 N프레임 연속 검출되면 이벤트로 본다(예: 15fps 기준 5프레임).
3. **2차(이벤트 시만)**: 박스 주변 20% 여백 크롭과 전체 프레임을 VLM에 보내 예/아니오와 근거를 받는다. 3070은 Qwen3-VL-4B 4bit, 4070은 Qwen3-VL-4B BF16이나 clef-flash 4bit.
4. **판정**: "예"일 때만 경보를 보낸다. "판단불가"는 사람 확인 큐로 보낸다. clef-flash를 쓴다면 p(true) ≥ 0.8 같은 확률 임계값으로 바꿀 수 있다.

예시 프롬프트:
- `현재 이미지는 화재나 연기가 있나요? 예/아니오와 근거를 답하세요. 반드시 JSON으로만: {"answer": "예|아니오|판단불가", "reason": "한 문장"}`
- `작업자가 안전고리를 착용하고 있나요? 안전대를 몸에 착용만 하고 훅(죔줄)을 구조물에 체결하지 않았다면 "아니오", 훅이 보이지 않으면 "판단불가"로 답하세요. JSON으로만: {"answer": "...", "reason": "..."}`
- (영문 대체) `Is there fire or smoke in this image? Answer only JSON: {"answer": "yes|no|uncertain", "reason": "..."}`

Python 예시(transformers + bitsandbytes 4bit, Qwen3-VL-4B-Instruct, 모델 카드의 `apply_chat_template` 방식):

```python
# pip install -U "transformers>=4.57" accelerate bitsandbytes ultralytics pillow
import torch
from PIL import Image
from ultralytics import YOLO
from transformers import AutoProcessor, BitsAndBytesConfig, Qwen3VLForConditionalGeneration

VLM_ID = "Qwen/Qwen3-VL-4B-Instruct"
bnb = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",
    bnb_4bit_compute_dtype=torch.bfloat16,   # RTX 30/40 계열은 bf16 지원
    bnb_4bit_use_double_quant=True,
)
vlm = Qwen3VLForConditionalGeneration.from_pretrained(
    VLM_ID, quantization_config=bnb, device_map="auto"
)
processor = AutoProcessor.from_pretrained(VLM_ID)

def ask_vlm(image: Image.Image, question: str, max_new_tokens: int = 96) -> str:
    messages = [{"role": "user", "content": [
        {"type": "image", "image": image},
        {"type": "text", "text": question},
    ]}]
    inputs = processor.apply_chat_template(
        messages, tokenize=True, add_generation_prompt=True,
        return_dict=True, return_tensors="pt",
    ).to(vlm.device)
    with torch.inference_mode():
        out = vlm.generate(**inputs, max_new_tokens=max_new_tokens, do_sample=False)
    new_tokens = out[:, inputs["input_ids"].shape[1]:]
    return processor.batch_decode(new_tokens, skip_special_tokens=True)[0].strip()

def crop_with_pad(img: Image.Image, xyxy, pad: float = 0.2) -> Image.Image:
    x1, y1, x2, y2 = xyxy
    w, h = x2 - x1, y2 - y1
    return img.crop((max(0, int(x1 - pad * w)), max(0, int(y1 - pad * h)),
                     min(img.width, int(x2 + pad * w)), min(img.height, int(y2 + pad * h))))

# 1차: 자체 학습·검증한 YOLO26 가중치(경로는 예시)
detector = YOLO("weights/fire_smoke_yolo26s.pt")
frame = Image.open("frame.jpg").convert("RGB")
result = detector.predict(frame, conf=0.3, verbose=False)[0]

Q_FIRE = ('현재 이미지는 화재나 연기가 있나요? 예/아니오와 근거를 답하세요. '
          '반드시 JSON으로만: {"answer": "예|아니오|판단불가", "reason": "한 문장"}')
for box in result.boxes:
    name = result.names[int(box.cls)]
    if name in ("fire", "smoke"):          # 학습한 클래스명에 맞게 수정
        crop = crop_with_pad(frame, box.xyxy[0].tolist())
        print(name, float(box.conf), ask_vlm(crop, Q_FIRE))
```

### 판단 요약

- **대상 구간(10-06)**: 3070/4070용 경량 신규 VLM이나 화재·PPE 탐지 가중치는 확인되지 않았다. 구간 안에서 확인된 것은 Ultralytics v8.4.174(YOLO26 AutoBatch 등 패치)뿐이다. OpenBMB `MiniCPM-V-4.7-35B-A3B`(35.2B MoE, 카드·라이선스 없음)는 공개 시각이 구간 경계라 날짜 미확정으로 두었고, 경량도 아니다.
- **공백기간 최대 신호는 `Cloudflare/clef-flash`(10-01, 9B, Apache-2.0)**: 이미지와 "예/아니오" 질문을 받아 확률을 바로 내는 결정형 오픈웨이트로, 이 리포트의 "화재 있나요? / 안전고리 착용했나요?" 패턴과 형식이 정확히 맞는다. 다만 9B라 3070은 4bit로 빠듯하고 4070이 현실적이다. 산업안전 정확도와 양자화 호환성은 직접 검증해야 한다. 같은 결정형인 Liquid AI d1(10-05 비전 지원)은 API 전용이라 참고만 한다.
- **탐지 쪽**은 fireviewer RF-DETR 화재/연기 모델 편입(09-30)과 rfdetr 1.11.2·Ultralytics 패치 외에 신규 아키텍처가 없다. YOLO27은 발표만 됐고 가중치는 미공개다.
- **권장 구성은 변하지 않았다**: YOLO26/RF-DETR 1차 → Qwen3-VL-4B(3070 4bit / 4070 BF16·8bit) 2차 확인. 4070에서는 clef-flash 확률형 2차 확인을 A/B 테스트할 것을 권고한다.

### 프롬프트 인젝션 점검

- transformers PR #44314 본문에 기여자·코딩 에이전트를 대상으로 한 체크리스트("For each class/method/... does an existing model ... already provide this ... If any answer is 'no checkpoint' or 'already provided', delete it.")가 있었다. 이 작업과 무관한 개발 지침이라 **따르지 않았고**, 악성으로 보이지 않는다.

### Caveat

- **HF 직접 검증 불가**: huggingface.co가 프록시에서 차단돼 저장소 `createdAt`/`lastModified`, 파일 크기, 라이선스 파일, 카드 원문을 직접 확인하지 못했다. 날짜와 수치는 모두 2차 출처(검색 결과 요약, GitHub의 다이제스트·릴리스 페이지)에 근거한다. 검색 요약과 fetch 요약은 모델이 생성한 텍스트라 오류가 있을 수 있다(예: GitHub 릴리스 연도가 2024로 잘못 요약됨).

- **검색 한도 소진**: 세션 공용 WebSearch 한도(턴당 200회)가 소진돼 `fireviewer/*-v2.5`·`SalahALHaismawi/yolov26-fire-detection`의 생성일 확인 쿼리 2건을 실행하지 못했다. 다음 회차에 확인한다.
- MiniCPM-V 4.7의 HF 생성 시각은 확인하지 못했다(감시봇 탐지 시각만 확인). Liquid d1 비전 발표의 KST 시각도 확인하지 못했다.
