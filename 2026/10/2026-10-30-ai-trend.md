## Threads와 주요 AI 이슈

### 화면과 명령을 합친 모델: 권한과 실증 범위가 핵심

**확인 사실.** [Mage-VL-Cowork 저장소 이력](https://huggingface.co/api/models/microsoft/Mage-VL-Cowork/commits/main)은 생성 **30일 12:13:24 UTC(21:13 KST)**, 카드·가중치 커밋 **12:14:43 UTC(21:14 KST)**를 표시한다. [공식 모델 카드](https://huggingface.co/microsoft/Mage-VL-Cowork)는 화면 이미지에서 GUI 동작을 고르는 `computer_use`와 명령 실행 `bash`를 한 정책에 결합했다고 설명한다. 카드의 ‘4B’는 급별 표기이고 Hub safetensors 계수는 **4,741,793,792개**, BF16 두 파일의 합은 **9,483,668,136바이트**(파일 바이트 합; 계산값)다. Apache-2.0, 훈련·평가 문맥 32,768토큰이다. 제작자는 OSWorld-Verified 50단계 조건에서 66.0%라고 보고한다. 독립 재현·한국어 GUI·macOS 호환 검증은 없다.

**적용 판단.** 화면 해석과 구조화된 파일 작업을 언제 나눌지 연구하는 후보지만, 원문은 실행 가능한 명령과 클릭을 생성하므로 일회용 VM·네트워크 허용목록·비밀키 제외·사람 승인을 요구한다. 실제 카메라·로봇을 조작하는 모델로 소개하지 않는다. 프롬프트·화면의 비신뢰 텍스트를 명령으로 그대로 옮길 위험을 별도 평가해야 한다.

### 작은 VLM의 배포 파일: 용량은 실행 메모리가 아니다

**확인 사실.** [OptiQ 커밋](https://huggingface.co/api/models/mlx-community/LFM3-VL-2B-OptiQ-4bit/commits/main)은 **30일 04:57:18 UTC(13:57 KST)** 변환본 게시를 표시한다. [모델 카드](https://huggingface.co/mlx-community/LFM3-VL-2B-OptiQ-4bit)는 언어 가중치에 혼합 4/8비트를 적용하고 비전 인코더는 BF16 별도 파일로 보존했다고 설명한다. Hub 파라미터 계수는 **1,728,801,536개**, 두 safetensors 파일은 각각 1,310,381,146바이트와 378,777,028바이트(합 약 1.69GB, 계산값). 카드는 디스크 약 1.7GB라고 적는다. 라이선스 필드는 `other`이며 원본 [LiquidAI 카드](https://huggingface.co/LiquidAI/LFM3-VL-2B)는 **LFM Open License v1.0**을 명시한다. 상업 이용 가능성을 Apache·MIT로 단정하지 말고 원문 조건을 읽어야 한다. 이미지 질의응답·문서/차트/영상 이해가 용도이고, 원본은 128K 문맥을 제공하나 긴 영상의 프레임과 KV 캐시는 별도 메모리를 쓴다. 양자화본의 카드 평가점수는 제작자 비교로 독립 재현 아님.

**추가 후보.** [PaddleOCR-VL-1.6 Manga](https://huggingface.co/hoanglovellm/paddleocr-vl-1.6-manga)는 **30일 13:18 UTC(22:18 KST)** 생성된 기존 OCR의 일본어 만화 특화 가중치다. 905,601,648개 FP16 파라미터, 단일 safetensors 1,811,279,728바이트. 원본 Apache-2.0을 계승한다고 카드에 기재되지만 저장소 license 필드는 비어 있어 재배포 조건 확인 필요. 한글 현장 OCR 적합성을 주장할 근거가 없고, 페이지의 위치 탐지·읽기 순서는 별도 구성요소가 필요하므로 이번 우선 검토에서는 제외한다. [Mobilint Qwen3-VL-2B 정적 변환](https://huggingface.co/mobilint/Qwen3-VL-2B-Instruct-static-Batch16-aries-rb)은 **30일 05:46 UTC** 생성됐으나 ARIES-RB NPU 전용으로 mini PC/GB10의 일반 가중치가 아니다.

### YOLO는 새 모델이 아니라 CPU 런타임 수정

**확인 사실.** [8.4.193 릴리스](https://github.com/ultralytics/ultralytics/releases/tag/v8.4.193) 게시 **30일 00:13:43 UTC(09:13:43 KST)**. CPU ONNX Runtime·OpenVINO 추론 경로의 PyTorch 전후처리 스레드를 최대 두 개로 제한해 런타임과 경쟁을 줄이고, 동적 내보내기 모델이 저장한 영상 크기를 기본값으로 복원한다. 제작자 시험에서 8-vCPU 조건 **19–54%** 빨라졌고 4-vCPU는 대부분 변화가 없거나 일부 ONNX 배치는 느려졌다. `.pt` 경로는 변경 대상이 아니고 새 YOLO 구조·가중치 발표도 아니다. 기존 [YOLO26 문서](https://docs.ultralytics.com/models/yolo26/)의 나노 탐지 모델 **2.4M** 파라미터는 융합·사용하지 않는 가지 제거 후 수치이며, 사전학습 체크포인트와 계수가 다를 수 있다. 박스 탐지와 인스턴스·의미 분할은 VLM OCR과 별도의 과제다. 소스는 AGPL-3.0 또는 기업 라이선스다.

**적용 판단.** CPU mini PC에서 기존 탐지·분할 모델을 ONNX/OpenVINO로 내보낸 경우 동일 영상·해상도·배치·스레드 수의 전후 지연과 재현율을 직접 비교한다. NVIDIA GB10의 CUDA 추론, Apple Metal, 특정 카메라의 지연과 메모리 개선을 이 릴리스로 보증하지 않는다. [8.4.194](https://github.com/ultralytics/ultralytics/releases/tag/v8.4.194)는 한국시간 31일 릴리스이므로 대상일 변화로 포함하지 않았다.

[원본](https://github.com/RAKKUNN/vicem)은 24일 생성한 MIT 로컬 CLI·MCP·스킬 도구로 에이전트 사이 작업 메모를 `.vicem/BATON.md`로 전달한다. 공개 README에 토큰 절감치가 있으나 독립 실험이 없어 수치 확정은 유보한다. 규칙 파일과 세션 기록에 접근하므로 비밀 유출·지시문 오염을 먼저 감사해야 한다. [통계 인용 글](https://news.hada.io/topic?id=36254)은 **29일 22:44 UTC = 30일 07:44 KST**에 GeekNews에 게재됐으나 [연구 원문](https://trakkr.ai/trakkr-research/zombie-stats)은 자체 인용에 **28일 발표**로 표시한다. 따라서 30일 *새 연구 발표*가 아닌 대상일 커뮤니티 소개다. 원문은 인용 통계 1,285개를 추적해 원연구와 일치한 비율을 40%로 추정하며, 표본·방법에 따라 일반화에 제한이 있다.

Toss Tech는 확인된 최신 노출 AI 글의 실제 게시일이 **27일**, 로그 스킬 글은 **23일**이다. Inpa의 RSS 첫 글은 2024-03-25, Goddaehee RSS 첫 AI 글은 **10월 8일**. **세 블로그의 대상일 신규 게시물은 공개 홈·피드 확인 범위에서 발견하지 못했다**. 이전 글을 날짜만 바꿔 오늘 소식으로 재사용하지 않는다.

## GitHub 급상승 기술과 30일 중복 확인

GitHub 누적 스타 또한 기준시각 스냅숏과 비교하지 않으면 ‘하루 증가’를 입증하지 못한다. `expo/skills`의 확인 가능한 최신 커밋은 **28일 20:07 UTC = 29일 05:07 KST**여서 30일 새 기능으로 다루지 않는다.

## AI/Vision 업무 적용 판단과 한계

1. **현장 배포 판단:** 기존 YOLO의 CPU 배포 지연을 먼저 같은 입력 조건에서 측정하고, VLM에는 별도 이미지 질의·OCR 정확도 집합을 쓴다. 제작자 데스크톱 벤치마크나 작은 파일 크기로 실시간성과 메모리 한계를 대신하지 않는다.
2. **로컬 실행 및 라이선스:** Mac mini의 16/24/32/48/64GB 구성과 GB10의 128GB는 하드웨어 공식 사양이나 현재 장치의 여유 메모리는 아니다. 대상 장치의 실제 RAM·VRAM, 런타임 지원, 이미지 해상도, KV 캐시, 긴 영상 입력, 양자화 후 한국어 오류를 각각 확인한다. LFM 라이선스와 YOLO AGPL/기업 조건도 검토한다.
3. **에이전트와 공공 데이터:** 허가 없는 명령 실행을 금지하고 공개·비식별 공공 데이터만으로 `korea-data-mcp`의 정규화값과 원 API 필드를 교차 검증한다. 외부 MCP·스킬은 설치 후크·쓰기 범위·네트워크를 감사하기 전 고객 자료와 연결하지 않는다.
4. **증거 공백:** Threads 대상일 AI permalink, Toss 전체 글 목록, 모든 Hub의 변경 이력, 대상일의 GitHub 과거 Trending, 모델별 mini PC·GB10 피크, 독립 성능 재현과 일부 행사 재고는 이번 조사에서 확인하지 못했다. 검색 후보나 한국시간 31일 발표를 30일의 새 소식으로 전용하지 않았다.
