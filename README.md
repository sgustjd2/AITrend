## 일일 조사 범위와 산출물

매일 실행일의 Asia/Seoul 기준 전날을 대상으로 Threads의 `@choi.openai`, Hugging Face의 신규·갱신 경량 VLM, YOLO 등 비전 모델, GeekNews, Toss Tech, Inpa, Goddaehee, GitHub Trending의 AI 스킬·플러그인·에이전트 프로젝트를 확인합니다. 각 출처의 실제 확인 범위와 접근 상태를 남기고, 원문 게시일·모델 저장소 갱신일·스타 증가 근거를 확인할 수 없는 항목은 최신 정보나 급상승으로 단정하지 않습니다.

모델별로 파라미터 수, 라이선스, 양자화, 작업 특성, 메모리 요구량과 한계를 정리합니다. mini PC는 탑재 GPU/메모리에 따라 다르게 평가하고, GB10 보드 적합성은 공식 하드웨어 사양과 모델 요구량을 대조합니다. 확인된 수치와 추정치는 구분합니다. 동일 GitHub 프로젝트는 최근 30일 리포트와 비교해 반복 소개를 피합니다.

결과는 `YYYY/MM/YYYY-MM-DD-ai-trend.md`와 출처별 확인 증거인 `YYYY/MM/YYYY-MM-DD-ai-trend.sources.json`에 저장합니다. 검증된 카드뉴스 결과물도 날짜별로 보관합니다. 매일 해당 날짜의 산출물만 별도 커밋으로 저장소 `GO9ME/AITrend`에 푸시합니다.

## 파이프라인 설계

### 1. 날짜 경계를 정확히 자른다

"오늘의 AI 트렌드"를 만들려면 **어제 00:00~23:59(KST)** 에 올라온 것만 골라야 합니다. 그런데 소스마다 시각 표기가 다릅니다.

| 소스 | 시각 표기 |
|---|---|
| Threads | `<time datetime="...">` — **UTC** |
| GeekNews | `<time title="...">` — **KST 절대시각** |

각 소스의 시각 속성을 파싱해 **전부 KST로 환산한 뒤 구간 필터링**합니다.

화면에 보이는 "3시간 전" 같은 상대 시각은 쓰지 않습니다. 수집 시점에 따라 날짜가 어긋나기 때문입니다.

### 2. 수집 실패를 숨기지 않는다

**이 파이프라인에서 가장 중요한 설계입니다.**

비로그인 상태에서는 최신 게시물이 4~7건만 노출되고, 스크롤하면 즉시 로그인 유도 화면으로 막힙니다. 게시 빈도가 높은 계정이면 **하루치를 다 훑지 못합니다.**

이때 리포트에 이렇게 남깁니다.

> **비고(중요)**: 이번 회차도 07-25 구간을 전혀 확인하지 못했습니다. 비로그인 상태로 노출되는 최신 게시물 7개를 전부 KST로 환산한 결과, 전부 07-26 새벽에 게시된 것으로 확인되어 목표 구간보다 뒤쪽입니다. 스크롤 2회 추가 시도했으나 즉시 로그인 유도 화면으로 막혔습니다.
>
> **결론**: 이번 회차도 이 계정에서 해당일의 실질적 이슈를 확인하지 못했습니다. 대신 GeekNews에서 확인된 이슈로 갈음합니다.

리포트에 반드시 남기는 네 가지 —

1. 무엇을 **못 봤는지**
2. **왜** 못 봤는지 (로그인 장벽, 노출 물량 한계)
3. 무엇을 **시도**했는지 (스크롤 2회 등)
4. 어떻게 **갈음**했는지 (대체 소스)

**이유** — 자동 생성 리포트가 조용히 빈 구간을 만들면, 읽는 사람은 "그날은 소식이 없었나 보다"로 오해합니다. 커버리지 실패는 누락이 아니라 **데이터의 일부**이므로 본문에 남깁니다.

### 3. 범용 뉴스가 아니라 목적에 맞춰 거른다

"오늘의 AI 뉴스" 요약은 이미 널려 있습니다. 이 리포트는 **구체적인 제약과 용도**를 기준으로 필터링합니다.

- **하드웨어 제약** — RTX 3070 / 4070에서 실제로 구동 가능한 경량 모델
- **용도** — 산업 안전 체크 VLM (화재·연기 감지, PPE 착용 여부, 낙상 감지)

그래서 모델을 나열하는 데서 끝내지 않습니다.

- 파라미터 수와 양자화 형식으로 **해당 GPU에서 돌아가는지** 판정
- 모델 저장소의 **최종 커밋일을 확인**해 "업데이트된 것처럼 보이지만 실은 신규 아님"을 걸러냄
- **역할 분담 제안** — VLM은 맥락 설명, YOLO는 실시간 박스 탐지
- 용도별 추천을 최종 가이드로 정리

### 4. 검증 경로를 항상 남긴다

각 항목에 **출처 링크 · 게시 시각(KST) · 커뮤니티 반응 지표**를 함께 기록합니다. LLM 생성물을 검증 없이 신뢰하지 않기 위한 장치입니다. 읽는 사람이 원문으로 바로 갈 수 있어야 합니다.

## 일간 기사 카드뉴스

카드뉴스는 편집 매거진처럼 표지와 상세 장면을 이어 읽는 4:5 세로형 캐러셀입니다. 표지는 짙은 잉크색 바탕 위에 리드 기사 하나를 크게 보여 주고, 나머지 기사는 번호가 붙은 목록으로 정리해 정보의 우선순위를 분명히 합니다. 상세 장은 밝은 종이색, 넉넉한 여백, 절제한 코발트 강조, 일관된 출처·페이지 표기를 사용합니다. 각 기사에는 주제별 삽화와 눈에 보이는 `AI 삽화` 캡션을 붙입니다. 삽화는 설명용 시각 자료이며 사실의 근거나 실제 사건 사진처럼 다루지 않습니다.

### 입력과 결과

| 파일 | 용도 |
|---|---|
| `YYYY/MM/YYYY-MM-DD-ai-trend-card.json` | 표지·기사 카드의 문안, 근거, 출처, 삽화 경로 |
| `previews/YYYY-MM-DD-ai-storybook-article.png` | 첫 장 미리보기 PNG |
| `previews/YYYY-MM-DD-ai-storybook-article-01.png` 이후 | 기사 상세 페이지 PNG |
| 각 PNG와 같은 이름의 `.svg` | 문구와 레이아웃을 수정할 수 있는 원본 |
| `team/assets/daily-briefing/` | 기사별 편집 삽화 |

### 기사 카드 작성 규칙

- `date`는 사전 점검의 `target=YYYY-MM-DD`를 그대로 사용하고, `headline`과 `deck`은 표지 문안으로 씁니다. 렌더러는 실제 달력 날짜인지 확인합니다.
- `issues`에는 출처로 검증한 기사 1~3개를 넣고, 각 항목에는 `title`, `summary`, HTTPS `source_url`, 한눈에 읽히는 사실 중심 `cover_summary`, 원문에서 확인한 `cover_fact`, 기사에 맞춘 `artwork`, `image_caption`을 작성합니다. 가능하면 `subtitle`, `evidence`, `impact`, `limitations`, `eyebrow`도 함께 기록합니다.
- 각 기사에는 해당 주제를 대표하는 삽화를 준비합니다. `artwork`에는 `/team` 기준 상대 경로를 넣고, `image_caption`에 `AI 삽화`를 포함합니다. 예: `assets/daily-briefing/example.png`. 다른 기사 이미지나 범용 장식 이미지를 대신 쓰지 않습니다. 삽화가 없으면 표지의 한눈 요약 품질 기준을 충족하지 못하므로 완성 카드로 표시하지 않습니다.
- 삽화 파일이나 캡션이 잘못되면 렌더러가 오류를 표시합니다. 빠진 그림을 조용히 다른 기사 그림으로 바꾸지 않습니다.
- 문안은 기사 원문과 대조하고, 기업 발표 수치·주장에는 발표 주체를 표시합니다. 확인되지 않은 주장이나 그림 안의 가짜 글자·수치·로고는 넣지 않습니다.

### 렌더

저장소 루트에서 실행합니다.

```bash
python3 team/scripts/render-ai-trend-card.py \
  AITrend/YYYY/MM/YYYY-MM-DD-ai-trend-card.json \
  --output AITrend/previews/YYYY-MM-DD-ai-storybook-article.png
```

현재 시각 규칙과 여백 기준은 [카드 디자인 가이드](../team/daily-briefing-card-design.md), 렌더 구현은 [카드 렌더러](../team/scripts/render-ai-trend-card.py)에 있습니다.

### 일일 크론 스크립트

`scripts/cron/`에는 중복 산출물을 확인하는 사전 점검기와 카드 JSON의 날짜를 파일명 기준으로 보정한 뒤 렌더링하는 래퍼가 있습니다. Hermes 크론 설정은 `~/.hermes/scripts/aitrend-preflight.sh`와 `~/.hermes/scripts/render-ai-trend-card.sh` 경로를 사용하며, 이 경로는 이 저장소의 스크립트를 가리키도록 연결합니다.
